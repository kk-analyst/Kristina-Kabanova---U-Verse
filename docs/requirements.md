# Requirements

## Цель

Показать, как бизнес-задача U-Verse декомпозируется до проверяемых функциональных требований.

## Основные функциональные области

### Loyalty

- просмотр текущего количества баллов;
- просмотр эквивалента баллов;
- просмотр срока действия;
- история начисления и списания;
- применение промокодов;
- использование баллов при покупке в пределах установленного ограничения;
- аудит операций лояльности.

### Course Payments

- создание заказа;
- применение промокода;
- расчёт итоговой стоимости;
- переход на внешнюю платёжную форму;
- получение результата оплаты через webhook;
- изменение внутреннего статуса платежа;
- получение актуального статуса из собственной БД;
- уведомление пользователя.

### Teacher Recruitment

- создание заявки кандидата;
- просмотр списка заявок администратором;
- фильтрация и пагинация;
- просмотр деталей;
- добавление комментария;
- изменение статуса;
- массовая обработка заявок;
- работа с документами кандидата;
- отправка уведомления кандидату при соответствующем переходе статуса.

## Примеры требований

| ID | Требование | Область |
|---|---|---|
| FR-001 | Система должна позволять авторизованному студенту просматривать текущий баланс бонусных баллов. | Loyalty |
| FR-002 | Система должна сохранять историю операций начисления и списания баллов. | Loyalty |
| FR-003 | Frontend не должен самостоятельно определять успешность платежа по successUrl/failUrl. | Payments |
| FR-004 | Актуальный статус платежа должен определяться Backend на основании данных U-Verse. | Payments |
| FR-005 | Backend должен проверять права администратора перед операциями с заявками преподавателей. | Teacher Recruitment |
| FR-006 | Для заявок должна поддерживаться фильтрация по предусмотренным параметрам и пагинация. | Teacher Recruitment |

## Нефункциональные требования и ограничения

В проектных материалах отдельно прорабатываются требования к:

- логированию;
- мониторингу;
- корректности формата данных;
- авторизации и ролям;
- ограничениям внешних API;
- обработке ошибок интеграций.

Конкретные значения приведены в соответствующих API и integration documents.
