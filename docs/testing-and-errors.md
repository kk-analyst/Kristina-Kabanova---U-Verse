# Testing & Error Handling

## API testing

При подготовке API-сценариев учитываются:

- позитивный сценарий;
- отсутствие авторизации;
- недостаточность прав;
- некорректные входные данные;
- отсутствие сущности;
- конфликт состояния;
- timeout внешней системы;
- некорректный ответ интеграции;
- ошибка БД.

## Payments

| HTTP | Сценарий |
|---|---|
| 400 | некорректный webhook |
| 403 | нет права создать платёж |
| 500 | ошибка сохранения в БД |
| 502 | ошибка/некорректный ответ RaifPay |
| 504 | timeout RaifPay |

## Teacher Recruitment

Для списка заявок прорабатываются:

- 200 — успешный ответ, включая пустой результат;
- 400 — некорректные параметры фильтров/пагинации;
- 401 — недействительная/отсутствующая авторизация;
- 403 — пользователь не ADMIN;
- 503 — сервис недоступен.

## Negative scenarios

### Webhook пришёл с некорректными данными

Backend не изменяет состояние платежа, фиксирует ошибку и возвращает 400.

### Внешний сервис не отвечает

Backend фиксирует timeout и возвращает соответствующий 504; пользовательский сценарий не должен трактовать отсутствие ответа как успешную оплату.

### Внешний ответ имеет некорректную структуру

Backend не использует неполный ответ для изменения данных U-Verse и фиксирует интеграционную ошибку.

### Неизвестный статус

Frontend не изменяет состояние самостоятельно и отображает пользователю, что статус уточняется.
