# REST API

Ниже собраны наиболее показательные API-контракты из проектного кейса.

## Найм преподавателя

### Получение списка заявок

`GET /api/v1/applications`

Назначение: получение списка заявок преподавателей для администратора.

Показательные параметры/требования:

- пагинация;
- сортировка;
- фильтрация;
- авторизация;
- проверка роли ADMIN;
- валидация query-параметров.

Примеры ошибок:

| HTTP | Сценарий |
|---|---|
| 400 | некорректные параметры фильтрации/пагинации |
| 401 | пользователь не авторизован |
| 403 | недостаточно прав |
| 503 | сервис временно недоступен |

### Получение заявки

`GET /api/v1/applications/{id}`

Возвращает данные конкретной заявки.

### Добавление комментария

`POST /api/v1/applications/{id}/comments`

Сохраняет комментарий администратора к заявке.

### Изменение статуса

`PATCH /api/v1/applications/{id}/state`

Используется для изменения состояния заявки; в одном из сценариев переход инициирует асинхронную отправку email кандидату.

## Оплата курсов

### Создание заказа

`POST /orders`

Backend создаёт заказ, присваивает уникальный номер и сохраняет начальное состояние.

### Webhook

`POST /api/v1/payments/webhook`

Назначение: приём уведомления от RaifPay.

Backend проверяет:

- структуру запроса;
- обязательные параметры;
- подпись webhook;
- существование платежа;
- внешний идентификатор;
- соответствие суммы данным U-Verse.

### Получение статуса

Frontend получает актуальный статус из Backend U-Verse; Backend читает состояние из собственной БД и не использует синхронный запрос к RaifPay для каждого запроса пользователя.

## T-Bank

### Отправка платёжного реестра

`POST /api/v1/payment-registries/{registryId}/submit`

Метод вызывается после подтверждения реестра администратором.

Успешный ответ внешней интеграции предполагает асинхронную обработку и наличие `correlationId`.

Показательные ответы:

- 202 — запрос принят;
- 400 — ошибка валидации;
- 401 — нет авторизации;
- 403 — недостаточно прав;
- 404 — реестр не найден;
- 409 — недопустимый статус;
- 502 — ошибка внешнего сервиса;
- 504 — timeout.

### Получение статуса реестра

`GET /api/v1/salary/payment-registry/{paymentRegistryId}`

Используется Backend для периодической синхронизации статуса асинхронной операции.
