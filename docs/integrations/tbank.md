# Integration: T-Bank

## Purpose

Передача платёжного реестра и получение результата его асинхронной обработки.

## Participants

Admin → U-Verse Backend → T-Bank

## Business process

Реестры формируются **10-го и 25-го числа**. Администратор проверяет, подписывает/подтверждает и отправляет реестр.

Расчёт выплаты в проектной модели:

`sales − commission`.

## Request

U-Verse Backend вызывает:

`POST /api/v1/salary/payment-registry/create-submit`

Внутренний endpoint U-Verse:

`POST /api/v1/payment-registries/{registryId}/submit`

## Async processing

После принятия операции T-Bank возвращает идентификатор корреляции. Внутренний статус U-Verse — «Отправляется», внешний — `PROCESSING`.

Далее Backend выполняет polling внешнего API и синхронизирует финальное состояние.

## Rate / size constraints

В проектной документации зафиксированы ограничения:

- не более 1 запроса в секунду;
- до 8000 платежей в реестре.

## Errors

- 400 — ошибка данных;
- 401 — авторизация;
- 403 — права;
- 404 — реестр не найден;
- 409 — недопустимое состояние;
- 502 — ошибка T-Bank;
- 504 — timeout.

## Analyst focus

Ключевая часть интеграционного решения — разделение синхронного запроса на отправку и асинхронного процесса обработки результата.
