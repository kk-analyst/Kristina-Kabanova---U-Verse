# Use Cases

## UC-1 — Оплата курса с промокодом

**Actor:** Student

**Preconditions:**
- пользователь авторизован;
- курс выбран;
- доступен применимый промокод.

**Main flow:**
1. Student оформляет заказ.
2. Frontend вызывает Backend.
3. Backend создаёт заказ.
4. Пользователь вводит промокод.
5. Backend проверяет промокод.
6. Рассчитывается итоговая стоимость.
7. Пользователь переходит на платёжную форму.
8. Платёжный провайдер обрабатывает оплату.
9. Backend получает webhook.
10. Backend проверяет webhook и обновляет статус.
11. Frontend запрашивает актуальный статус.

**Key edge cases:** промокод недействителен, timeout, некорректный webhook, пользователь не вернулся в приложение.

## UC-2 — Просмотр списка заявок преподавателей

**Actor:** Admin

**Main flow:**
1. Admin открывает список.
2. Backend проверяет авторизацию и роль.
3. Валидируются параметры фильтрации и пагинации.
4. Backend получает данные.
5. Frontend отображает список.

**Errors:** 400 / 401 / 403 / 503.

## UC-3 — Изменение статуса заявки

**Actor:** Admin

1. Admin выбирает заявку.
2. Frontend отправляет PATCH.
3. Backend проверяет права и допустимость перехода.
4. Backend изменяет статус.
5. При соответствующем переходе инициируется асинхронное email-уведомление.
6. Frontend получает результат операции.

## UC-4 — Отправка платёжного реестра

**Actor:** Admin

1. Реестр сформирован.
2. Admin проверяет данные.
3. Admin подтверждает отправку.
4. Backend вызывает T-Bank.
5. T-Bank возвращает correlationId.
6. Backend сохраняет идентификатор.
7. Запускается polling.
8. Финальный статус синхронизируется с U-Verse.
